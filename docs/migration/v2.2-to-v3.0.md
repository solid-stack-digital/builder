# Migrate Builder 2.2.0 projects to 3.0.0

Builder 3.0.0 changes configuration and has no V2 fallback. It remains agnostic about the application's language and framework. For earlier installations, first read the historical [V1 to V2](v1-to-v2.md) or [V2.1 to V2.2](v2.1-to-v2.2.md) guide; their examples are not V3 syntax.

In V3, **requisites** decide which ordinary services run. Endpoint references configure already reachable services; they do not add edges. Mesh `extends` explicitly replaces V2 provider substitution. Each source and global tester has its own Compose implementation.

## Inventory and safe order

Inventory every `build.json`, `mesh.json`, stage overlay, project Dockerfile, ordinary Compose file, main override, tester file, `.env.dev`, `.env.prod`, `.env.test`, `.env.e2e`, `.env.e2e-tester`, application mode branch, endpoint reference, publication selection, Makefile, package script, and CI command. Record the installed 2.2.0 version and current runtime behavior, then back up configuration and data to a location you choose.

1. Stop existing 2.2.0 dev, prod, and test runs with that version's supported `down` commands in their original project directories. Decide separately whether any volumes may be removed; a blanket prune is not a migration step.
2. Convert each standalone source completely, including its tester and overrides. Validate it on its own.
3. Convert the mesh, source rewrites, publication and global tester.
4. Update application mode assumptions, scripts, endpoint references and selected override files.
5. Use a local V3 checkout or an installed V3 package, if available, for checks and dry runs. Inspect the compiled graph before live execution.
6. Run focused source tests, then the full mesh test. A project's first image build can take longer than Builder's own warmed verification budget.

Renamed Docker resources do not migrate persistent data. Plan retention for external volumes and databases separately.

## Field transformations

| V2.2 input | V3 replacement | Action |
|---|---|---|
| Missing/optional `name` | Required `name` | Name each build and mesh. |
| `app` | `services.main` | Define main runtime identity. |
| `dependencies.x` | `services.x` | Declare an ordinary module; add requisites to start it. |
| Implicit integrated inclusion | `main.requisites` or ordinary requisites | Use `dependency` to preserve healthy ordering. |
| `dependsOn` | `requisites` map | Convert each consumer edge. |
| Root `tester` | `services.tester` | Select a separate Compose runner. |
| Root stage `override-compose` | `<stage>.services.main.override-compose` | Select one final file. |
| Override `services.app` | Override `services.main` | Preserve allowed args, mounts and env. |
| Root `dockerfile` customization | Canonical project `Dockerfile` | Put main `dev`, `test`, `prod` targets there. |
| Mesh `path` | Mesh `source` | Source path remains immutable across overlays. |
| Mesh direct `env` | `extends.main.env` | Preserve authoring origin and precedence. |
| Mesh provider map | Explicit `false` prune + requisite + env rewrite | No automatic edge/reference translation. |
| Mesh root `tester` | `services.tester` | Supply global Compose and selected runner. |
| `app.endpoints.x` | `main.endpoints.x` | Update local references and selectors. |
| `dependencies.x.endpoints.y` | `x.endpoints.y` | Refer to the retained local module. |
| `meshName.app.endpoints.x` | `meshName.source.main.endpoints.x` | Use canonical cross-source grammar. |
| `meshName.dependencies.x.endpoints.y` | `meshName.source.x.endpoints.y` | Refer to an actual retained local node. |
| Accumulated `publish` arrays | Replacing arrays | Restate every desired selector in an overlay. |
| Inert endpoint-less declaration | Ordinary module with explicit `service` | Use a requisite; jobs usually use `prerequisite`. |
| Main `test-e2e` target | Separate tester Compose image/build | Keep test dependencies in that runner. |
| Tester `EXEC_MODE=e2e` | Tester-specific command/config | App E2E remains prod/integrated. |
| Public `mesh up test-e2e` | `mesh up test` | Runs both source and global phases. |

`mesh.json.test` was already removed by 2.2.0; its continued rejection is not a new V3 change.

The [before fixture](../examples/docs-migration-pair/before/README.md) preserves the historical JSON, and the [after fixture](../examples/docs-mesh/mesh.json) contains runnable source, tester, Dockerfile and override assets. The [standalone fixture](../examples/docs-service/build.json) uses the same migrated frontend source.

## Standalone source: complete before and after

Historical V2.2 `services/frontend/build.json` (before):

```json
{
  "name": "frontend",
  "app": {
    "endpoints": { "http": { "port": 3000, "publicPort": "AUTO", "primary": true, "scheme": "http" } },
    "env": { "BACKEND_URL": "http://localhost:8080" }
  },
  "dependencies": {
    "backend": {
      "compose": "./compose/mock-backend.yml",
      "endpoints": { "http": { "service": "backend", "port": 8080, "primary": true, "scheme": "http" } }
    }
  },
  "tester": { "env": { "API_URL": "${app.endpoints.http.public_url}" } },
  "prod": { "app": { "env": { "BACKEND_URL": "${dependencies.backend.endpoints.http.network_url}" } }, "override-compose": "./overrides/prod.yml" }
}
```

V3 `services/frontend/build.json` (after, complete file):

```json
{
  "name": "frontend",
  "services": {
    "main": {
      "endpoints": { "http": { "port": 3000, "publicPort": "AUTO", "primary": true, "scheme": "http" } },
      "requisites": { "backend": "dependency" },
      "env": { "BACKEND_URL": "http://localhost:8080" }
    },
    "backend": {
      "compose": "./compose/mock-backend.yml",
      "service": "backend",
      "endpoints": { "http": { "service": "backend", "port": 8080, "primary": true, "scheme": "http" } }
    },
    "tester": {
      "compose": "./e2e/docker-compose.yml",
      "service": "e2e-runner",
      "env": { "API_URL": "${main.endpoints.http.public_url}" }
    }
  },
  "prod": { "services": { "main": {
    "env": { "BACKEND_URL": "${backend.endpoints.http.network_url}" },
    "override-compose": "./overrides/prod.yml"
  } } },
  "e2e": { "services": { "main": { "env": { "TEST_KIND": "black-box" } } } }
}
```

The base/test value stays isolated-safe; the external endpoint expression appears in integrated prod/E2E. `compose/mock-backend.yml` must contain service `backend` with a healthcheck if it is a dependency. The project Dockerfile needs healthy `dev` and `prod` targets.

Historical `services/frontend/overrides/prod.yml` (before):

```yaml
services:
  app:
    build:
      args:
        FEATURE: "on"
    environment:
      LOG_LEVEL: info
```

V3 `services/frontend/overrides/prod.yml` (after):

```yaml
services:
  main:
    build:
      args:
        FEATURE: "on"
    environment:
      LOG_LEVEL: info
```

An E2E `override-compose` path replaces the prod path; it does not stack files. Consolidate needed mounts, environment, and build arguments into the selected file. The override may not replace Builder's target, ports, network ownership or health contract.

## Extract the tester

Historical project `Dockerfile` included `dev`, `test`, `test-e2e`, and `prod` targets. Keep the application's `dev`, `test`, and `prod` targets in that file. Move the old E2E runner's dependencies, copied test assets, entrypoint and actual test command into `services/frontend/e2e/Dockerfile`:

```dockerfile
FROM node:20-alpine
WORKDIR /test
COPY e2e/package*.json ./
RUN npm ci
COPY e2e/ ./
CMD ["npm", "test"]
```

`services/frontend/e2e/docker-compose.yml` (complete file):

```yaml
services:
  e2e-runner:
    build:
      context: ..
      dockerfile: e2e/Dockerfile
    network_mode: host
  test-helper:
    image: alpine:3.20
    command: ["sh", "-c", "exit 0"]
```

Host networking lets the runner reach a `${main.endpoints.http.public_url}` that resolves to loopback. For a network URL instead, choose explicit bridge networking and reachable DNS. The `service` field selects `e2e-runner`; a helper's exit never determines the result. `.env.e2e` feeds the application, while `.env.e2e-tester` feeds the runner. E2E does not load `.env.prod` automatically and Builder gives testers no `EXEC_MODE`, `INFRA_MODE`, or `PORT`. `builder service up test-e2e` remains a standalone workflow convenience, not a required main Dockerfile target.

## Mesh: two source roots and explicit replacement

Historical V2.2 `mesh.json` (before, complete file):

```json
{
  "name": "frontend-system",
  "services": {
    "backend": { "path": "./services/backend" },
    "frontend": { "path": "./services/frontend", "dependencies": { "backend": "backend" }, "env": { "BACKEND_URL": "${backend.app.endpoints.http.network_url}" } }
  },
  "tester": { "compose": "./e2e/docker-compose.yml", "service": "global-runner", "env": { "API_URL": "${frontend.app.endpoints.http.public_url}" } }
}
```

V3 `mesh.json` (after, complete file):

```json
{
  "name": "frontend-system",
  "services": {
    "tester": { "compose": "./e2e/docker-compose.yml", "service": "global-runner", "env": { "API_URL": "${frontend.source.main.endpoints.http.public_url}" } },
    "backend": { "source": "./services/backend" },
    "frontend": {
      "source": "./services/frontend",
      "publish": ["main.endpoints.http"],
      "extends": {
        "main": {
          "requisites": { "source.backend": false, "backend": "dependency" },
          "env": { "BACKEND_URL": "${backend.source.main.endpoints.http.network_url}" }
        }
      }
    }
  }
}
```

The block at `services.frontend` removes its local backend **edge**, adds a healthy-ordering edge to the real backend root, and rewrites the URL. It does not delete the local declaration or infer an edge from a reference. If an ordinary `worker` in frontend also consumed the mock, override `extends.worker.requisites` with `"source.backend": false, "backend": "dependency"` and `extends.worker.env` with the real URL; changing main does not rewrite nested consumers. An overwritten stale reference is harmless, while a surviving stale reference fails. Different endpoint names require explicit rewrite.

The global `e2e/docker-compose.yml` selects `global-runner` and has its own image/build; source testers are only used during Phase 1. If the global runner reads a loopback public URL, use explicit host networking as in the source runner example.

## Stages, publication and ordering

Arrays replace. For an already reachable main, inspection UI, and debug UI, a base `publish` of `["main.endpoints.http", "inspection.endpoints.ui"]` must be restated as `["main.endpoints.http", "inspection.endpoints.ui", "debug.endpoints.ui"]` in a dev overlay. Writing only `["debug.endpoints.ui"]` removes both earlier host bindings. Every selected endpoint needs `publicPort` and reachability. Publication does not add a requisite.

An E2E-only local `fixture-loader` declaration stays dormant until an E2E requisite points to it, often `"fixture-loader": "prerequisite"`. A top-level mesh source added in `e2e.services` instead becomes an E2E root; it is excluded from Phase 1 base-source tests. `dependency` waits for representative health, `prerequisite` waits for successful exit, and `requirement` only includes. Requirement-only cycles may exist; cycles among ordering edges fail. The same target cannot be both a dependency and prerequisite. Preserve a former healthy dependency with `dependency` unless you intentionally change ordering. Endpoint-bearing services need exactly one primary; endpoint-less modules need an explicit representative service. The E2E barrier checks every reachable long-running representative and prerequisite, plus main health.

## Environment and command migration

| Recipient | V3 rule |
|---|---|
| Main | Only main gets `EXEC_MODE` and `INFRA_MODE`; `PORT` is its primary internal port, not host port. |
| Ordinary module | Native Compose defaults followed by source and mesh env; one Builder env value reaches every module container. No main dotenv inheritance. |
| Main override | Selected override env follows source JSON and precedes mesh extends env. One file is selected. |
| Tester | Own `.env.e2e-tester` and tester JSON env; no main dotenv or lifecycle variables. |
| E2E | Structured prod overlays apply, then e2e overlays; `.env.e2e` replaces `.env.prod`. |

Only winning values are reference-validated. An active external reference in isolated mode still fails if its target is outside closure. See [environment precedence](../reference/environment-precedence.md).

Replace direct global `mesh up test-e2e` scripts with `mesh up test`. Audit Makefiles, package scripts and CI, and remove tester branches that assume `EXEC_MODE=e2e`. Validate the migrated tree in this order:

```text
builder --version
builder check -C ./services/frontend
builder check -C ./services/backend
builder service up prod --dry-run -C ./services/frontend
builder service up test --dry-run -C ./services/frontend
builder mesh check -C .
builder mesh up dev --dry-run -C .
builder mesh up test --dry-run -C .
builder service up test -C ./services/frontend
builder service up test -C ./services/backend
builder mesh up test -C .
```

Inspect the active node set, removed mock edge, main target and modes, selected runner, publication, separate env domains and cleanup after each run. A dry run validates composition, not engine health, job success or tester connectivity. Errors stop with nonzero status. The final mesh test deliberately repeats the source tests as Phase 1; the earlier source commands are useful migration diagnostics, not a routine requirement.

## Troubleshooting and recovery

| Symptom | Likely cause | Correction |
|---|---|---|
| Unknown `app`, `dependencies`, `path`, root `tester`, or `dependsOn` | V2 field remains | Apply the field table and explicit requisite rewrite. |
| Missing `name`, tester, or ordinary representative | Incomplete V3 declaration | Add required name, tester Compose/service, or endpoint-less `service`. |
| Target exists as another mesh root but reference fails | Outside consumer closure | Add an explicit requisite from that consumer. |
| Pruned target still referenced | Surviving env points to old node | Rewrite the winning value or retain the local edge intentionally. |
| Publication rejected | Selector grammar, capability, or reachability wrong | Use source-relative selector, `publicPort`, and a real requisite. |
| Host endpoint disappeared in overlay | Array replaced | Restate all desired `publish` selectors. |
| Stage changes `source` or `compose` | Immutable implementation replaced | Keep original path; change allowed env/requisite fields. |
| E2E job hangs or exits nonzero | Prerequisite never completes or fails | Inspect job logs and exit status; fix its command. |
| E2E main/module lacks health | Barrier cannot confirm readiness | Add a usable main/representative healthcheck. |
| Tester expects `EXEC_MODE=e2e` or old target | Obsolete runner contract | Give its own Compose command and config. |
| Wrong global result | Source tester/helper selected | Set mesh `services.tester.service` to the actual global runner. |
| Cleanup fails | Owned runtime may remain | Use saved runtime identity and supported project `down` command; inspect state before retry. |

To revert a local migration, stop V3 runtime first, restore backed-up source/config and the original package version, then validate with that version. This cannot restore data removed by volume deletion and cannot migrate persistent data between old and new resource names.
