# Migrate Builder 3.0.0 projects to 3.1.0

Existing V3 configuration remains valid. Builder 3.1.0 adds first-class Docker build arguments on the main service. Move simple values from a main `override-compose` file into `build.json` when stage-aware configuration or endpoint references are useful:

```json
{
  "services": {
    "main": {
      "buildArgs": {
        "BASE_PATH": "/web"
      }
    }
  },
  "prod": {
    "services": {
      "main": {
        "buildArgs": {
          "BUILD_MODE": "production"
        }
      }
    }
  }
}
```

Keep advanced Compose build settings in `override-compose`. On the same key, its `build.args` wins over source `buildArgs`; in a mesh, `extends.main.buildArgs` wins over the source override. E2E inherits source and mesh `prod` values before its `e2e` values. `.env.<stage>` files supply runtime values only. Builder validates only the references that survive precedence merging.

Use strings for every value, including booleans and numbers. `buildArgs` belongs only on `services.main` or a mesh source's `extends.main`; ordinary services and testers reject it. Keys beginning `BUILDER_` are reserved.

Build arguments can appear in build metadata, image history, caches, or logs. Keep secrets in build secrets or runtime configuration.
